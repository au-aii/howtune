iOS は AirPods のヘッドトラッキングという独自性のためネイティブのまま。その上に、リスナー本人と B2B（アーティスト/レーベル）の両方が見られる Web ダッシュボードをどう足すか。既存 Firebase を壊さずに拡張する段階プラン。

00 — 大原則

Firebase を単一の真実の源にして、Web は"窓"を足すだけ

バックエンドは作り直さない。iOS も Web も同じ Firebase を見る。センサーを扱う iOS が「収集する側」、Web が「読んで見せる側」。責務がぶつからないのがこの形の強み。

01 — Web の2つの顔

同じデータ源から、2種類の見せ方

本人向けは「生の自分のデータを直読み」、B2B は「匿名集計された結果だけを見せる」。ここを分けるのが設計の核。

Face A — リスナー本人

自分の振り返り

  • 自分がどの曲でどう反応したか
  • 反応履歴・心拍トレンド・お気に入り曲
  • iOS と同じアカウントでログイン

Firestore 直読み
rules: 本人のみ read

Face B — アーティスト / レーベル

B2B インサイト

  • 「楽曲のどこで聴衆が沸いたか」
  • 時間軸の反応密度ヒートマップ・タグ分布
  • 自分の曲の集計結果だけを閲覧

集計API（Functions）経由
匿名化済み song_insights のみ

02 — 段階ロードマップ

小さく出して、集計レイヤーを足して、B2B へ育てる

いきなり全部作らない。本人向けを最小で出し、その裏に集計を足し、最後に B2B 画面を載せる順。

P1本人向け

本人ダッシュボード（最小・すぐ出せる）

GOAL: 自分の反応を Web で見られる状態

  • Firebase Hosting に Next.js を立てる
  • Firebase Auth で iOS と同じアカウントでログイン
  • 自分の how-cards を Firestore 直読みで可視化
  • firestore.rules は「本人のみ read」で既存の延長
P2集計

集計レイヤー（B2B の土台）

GOAL: 曲ごとの匿名インサイトを前計算

  • Cloud Functions で曲ごとの反応を集計 → song_insights/{songId} に保存
  • 中身：時間軸の反応密度ヒートマップ・タグ分布・リスナー数
  • トリガー：how-card 作成時 or 定期バッチ
  • ⚠️ 匿名化必須：user_id を含めない／最小人数（例 5人）未満は出さない
P3B2B

B2B インサイト画面 ＋ 精緻化

GOAL: アーティストが自分の曲の反応を見られる

  • アーティスト認証と曲の所有権（自分の曲の song_insights のみ read）
  • ヒートマップ可視化（「サビの 1:12 で反応集中」）
  • iOS の自動検出リアクションを保存する API を追加新規し、秒単位で精緻化

🔒 k-匿名性：ある曲・ある区間の反応が最小人数（例：5人）未満なら表示しない。song_insights には user_id を一切含めず、集計値（人数・密度・タグ比率）だけを持たせる。

04 — 効く発見

既存の how-cards が、もう B2B の素材になっている

新しいデータを作らずに B2B 第一版が始められる

how-cards は既に song_id ＋ song_start/song_end ＋ tags ＋ user_id を持っている。これは「曲のこの区間で、この人が、こう反応した」という記録そのもの。曲ごとに集計すれば「どこで沸いたか」が出せる。

一方、AirPods の自動検出リアクション（ReactionEvent）は現状 iOS のメモリ上だけで Firestore に未保存（FirebaseAPI に保存メソッドが無い）。ここを保存すれば、秒単位のもっと細かい盛り上がりが取れる → Phase 3 の精緻化で追加する。

05 — 貫く設計原則

ここだけは外さない 3 つ

1

B2B には生データを渡さない。 アーティストが見るのは、Functions で集計・匿名化した song_insights だけ。個人の反応は特定されない。

2

書き込みは Functions、読み取りは Web 直読み。 既存の「2経路」の延長。本人ダッシュボードは直読み、B2B は集計 API。

3

iOS＝センサー主体 / Web＝閲覧主体で責務を分け、Firebase を共通の真実の源にする。バックエンドの二重実装を避ける。

次の一手（この作戦の実行順）

  1. Phase 1 を最小で立てる — Firebase Hosting に Next.js、Auth でログイン、自分の how-cards を直読みで表示。ここまでで「Web で自分の反応が見える」を達成。
  2. Phase 2 の集計を how-cards ベースで書く — 新データ不要。Functions で song_insights を作り、匿名化（k-匿名性）を最初から入れる。
  3. Phase 3 で B2B 画面と生反応保存を足す — アーティスト所有権とヒートマップ、そして ReactionEvent の Firestore 保存で秒単位に精緻化。
