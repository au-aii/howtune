# HowTune ビジョン / North Star

長期の狙い（moat とデータフライホイール）。2026-07 にオーナー(au-aii)が言語化。

## コア仮説

音楽体験の価値は「**身体的な反応**」にある。Apple Music 単体では取れない、より**低レイヤー**のデータ（頭部モーション・生理的シグナル・エンゲージメント）を取得し、それを **AI で解釈・活用**することが moat（競合が真似しにくい優位）。

## データフライホイール

1. **反応を記録** — AirPods 頭部モーション ＋（将来）心拍/生理シグナル ＋ 手動 How ＋ いいね等のエンゲージメント
2. **反応を「断定しない」** — AI(HowChat)が対話で解釈し、聴き方(How)を言語化する（ラベルの押し付けではなく対話）
3. **エンゲージメントがシグナルになる** — 「誰のコメントにいいねしたか」等が、その人の内的状態・嗜好を反映
4. **雰囲気ベースのレコメンド** — 蓄積したマルチシグナルから「その人の"雰囲気"に合う音楽」を推薦
5. レコメンドが新しい反応を生み、データが増える → 1 に戻る。**回るほど精度が上がる**

## 狙う独自データ（Apple Music では取れない拡張）

- **頭部モーション**（乗り方・ノリ）
- **生理シグナル**（将来: 心拍・ホルモン的 proxy 等、低レイヤーでの分解・判定）
- **エンゲージメント**（いいね＝内的状態の反映）
- **聴き方(How) のタグ・言語化**（AI 対話由来）

## 現状とのギャップ（最重要）

- 今 Firestore にあるのは **手動 How カードだけ**。
- **moat の核である生の AirPods 反応（`ReactionEvent`）・モーション・生理シグナルは未保存**（iOS のメモリ上で消えている）。
- → フライホイールを回すには、まず**これら生シグナルを蓄積する基盤**が要る。ここが最大の未着手ポイント。

## 段階（ビジョンへの道筋）

- **近**: `song_insights` 集計（反応の可視化＝フライホイールの最初の一回転）← 今ここ（Web ダッシュボード Phase 2）
- **中**: 生 `ReactionEvent` / モーションの Firestore 保存、いいね等の signal 化
- **遠**: 雰囲気ベースのレコメンド、低レイヤー生理シグナルでの分解・判定、高度なエンゲージメントアルゴリズム
