# 要求内容

## 概要

iOS アプリで記録した **自分の How カード**を Web で振り返る、本人向けダッシュボード（Phase 1）。既存 Firebase（`howtune-74252`）を単一の真実の源にして、**読み取り専用**で可視化する。

## 背景

- HowTune のコアはセンサー依存で iOS ネイティブが本体（ADR-0001）。だが「記録した聴き方の振り返り」は大画面の Web が適する。
- 最終的にリスナー本人向けと B2B インサイトの両方を想定（ADR-0007）。その最初の一歩＝本人向け直読み。
- バックエンドは作り直さず、既存 Firebase に「読む窓」を足すだけにする。

## 実装対象の機能

### 1. Firebase Auth ログイン

- iOS アプリと同じアカウント（メール/パスワード）でログインできる

### 2. 自分の How カード一覧

- Firestore を直読みし、`user_id == 自分` の how-cards を新しい順に表示
- 各カード: 曲/アーティスト・反応区間・コメント・いいね数・返信数・日付

### 3. サマリ

- How カード総数・総いいね数

## 受け入れ条件

- [x] iOS と同じアカウントでログインできる
- [x] 自分の how-cards が一覧表示される（他人のは出ない）
- [x] ライト/ダークが OS 設定に追従する
- [x] `npm install` / `npm run build`（型チェック含む）が通る
- [x] dev サーバーが起動しページを配信する（HTTP 200）

## 成功指標

- iOS で作った How カードが、同じアカウントの Web ログインで一覧に出る。

## スコープ外

以下はこのフェーズでは実装しない:

- B2B インサイト（`song_insights` 集計・匿名化）→ Phase 2 以降
- リアルタイム購読（`onSnapshot`）→ 今は都度取得
- Firebase Hosting へのデプロイ（別タスク）
- Web からの書き込み・編集（読み取り専用に徹する）
